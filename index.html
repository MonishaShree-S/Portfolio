01How I work

  1. Start from a real annoyance

    My longest-running project began because splitting supermarket receipts with flatmates was tedious. I have rebuilt it five times since.

  2. Put guardrails around the model

    A model that writes SQL will eventually write wrong SQL. I build the layer that catches it: rule models, rewrites, limits.

  3. Treat constraints as the brief

    One GPU, no data leaving the building, German-speaking users. Quantization and local inference are how the work gets done.

  4. Ship like a bank engineer

    Three years on a Citi project taught me release discipline. TLS, signed code and tested changes come with me into AI.

02One problem, five rebuilds

Since 2023 I have kept returning to one small problem: who owes whom after the grocery run. Each version is where I practised the next thing I wanted to learn.

  1. Dec 2023

    Can a receipt be read at all?

    OCR experiments on REWE and Kaufland receipts with Tesseract and cloud OCR APIs. Output: items, prices and quantities as JSON, then CSV to paste into Excel.

  2. May 2024

    One script

    A single Python file that takes expenses, splits them and prints who owes whom. Code ↗

  3. 2024 – 2025

    A web app with a database

    Flask front end, user accounts, an admin role and SQL Server behind it. Receipts are uploaded as PDFs and parsed into line items.

  4. Jul 2025

    Six services on Azure

    Sirantha RechnungSplit, my Master's software engineering project. Auth, invoice, split, debt and admin services plus a UI, each in its own container on Azure Container Apps, with JWT auth and EasyOCR. Code ↗

  5. 2026

    Still running, now automated

    A folder watcher imports new PDF receipts on its own, removes duplicates and flags the ones that need review. Photos of receipts go to an OpenAI vision model that returns the line items as structured JSON. An analytics dashboard sits on top, and I'm adding a retrieval layer to ask the data questions.
